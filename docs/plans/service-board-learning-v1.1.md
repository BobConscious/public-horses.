# Service board pilot plan

**Version** 1.1 · **Date** November 23, 2026 · **Decision** Private implementation and rehearsal

Use the four stages and measures in [plan v1.0](service-board-learning-v1.0.md). This revision adds the decisions from the [team debate](../decisions/service-board-pilot-debate-v1.0.md). The first goal is one result that the organizer confirms.

## Prepare the request

1. Copy the [request and results card](../operations/pilot-request-card-v1.0.md) into the private pilot record. Record one task, one organizer, and one response page.
2. Record the date, start time, time zone, time needed, and complete result. Give the reviewer an HTTPS page that confirms the request. Keep the review field private.
3. Use the same response page in both fields if it confirms the request. Ask the organizer who will keep availability current.

Organizer Success owns the card. Readiness and Evidence check the approved version and the exact listing. [Team review process](../agent-team.md#review-process)

## Check the handoff

Use a fictional organizer and a test page under your control. Use a non-demo listing to exercise the real response action. Record the build, listing version, test result, and evidence link.

| Case | Pass condition |
| --- | --- |
| Prepare and review | Read the schedule and proof hints. Enter the card and save the draft. A different reviewer checks the listed details and both links. The public view keeps the review field private. |
| Open | Find the request on a phone with a keyboard. The available **Time** action shows the availability hint. The controlled page accepts one test offer and returns a receipt. |
| Hint scope | Use a fixture with **Time** and another response type. Check that only **Time** shows the hint. Check that the hint stays hidden on demo, fulfilled, and expired listings. |
| Full | The same page shows that the request is full. A second offer produces no new receipt. The listing stays open in Public Horses while the work is pending. |
| Fulfilled | The organizer marks the request fulfilled after the controlled service. The board removes it from discovery and removes its response. The direct page still lets a supporter record past service. |
| Expired | Expire a published fixture through its end date. Check that the board removes its response and that the direct page still lets a supporter record past service. |
| Garden | Check that the garden shows one inline **Find a way to serve** link before and after the first seed. In a seeded garden, the journal action comes first. Use the board link with a keyboard. |
| Restore | Run the existing backup command with the source open. Open the restored database. Check fulfillment, the closed response, and one member’s original note and later observation. Check that another account has an empty garden. |

The COO owns the browser rehearsal. Engineering owns the recovery test. Use the [live acceptance gates](../pilot-acceptance.md#gates) for sign-in, recovery on the approved host, organizer consent, and Bob’s release decision.

## Record the outcome

The organizer keeps the response page current. Treat a full request as pending service. Use **Close opportunity** for a withdrawal. Use **Mark fulfilled** after the organizer confirms that the work met the stated need.

Ask if the organizer has a second suitable date. After the first confirmed act, offer the second task if it is approved, open, and has room. If it fills or closes, give the supporter the board link.

Record the repeat test only for people who consent. Count the people with a confirmed first act who received an eligible second offer. Report how many served a second time with organizer confirmation. Keep intentions and observations within the member’s garden. Mark missing outcomes as unknown.
